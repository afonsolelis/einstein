LABORATÓRIO 05

Metabase local com Docker: subindo a sua própria base

Na aula 4, o Metabase já estava de pé e o Olist já estava limpo. Aqui a situação se inverte: você sobe o servidor, decide onde os dados vão morar e carrega uma base hospitalar que ninguém preparou. A pergunta do dia é a de qualquer analista que recebe uma planilha por e-mail — podemos confiar nesta base? — e a resposta precisa vir em contagens, não em impressões.

⬇️ Baixar base CSV🐳 Baixar docker-compose.yml

1. Objetivos de aprendizagem

  • Subir Metabase e PostgreSQL na própria máquina com um único arquivo Docker Compose.
  • Configurar a conexão do banco analítico e o destino de uploads no Metabase.
  • Carregar um CSV bruto reconhecendo encoding, separador e tipos inferidos.
  • Escrever consultas que quantifiquem ausências, categorias duplicadas e cronologias impossíveis.
  • Defender um parecer de confiabilidade sustentado por números verificáveis.

2. Por que sair do Metabase compartilhado

O Metabase hospedado da aula 4 resolveu um problema de ensino: a turma inteira entrou pelo navegador e escreveu SQL no mesmo Olist, sem instalar nada. Ele também escondeu três decisões que, no trabalho, são suas:

  • Onde o dado mora. Uma conta compartilhada em servidor de terceiros não é para dado de paciente, de folha ou de faturamento.
  • Quem pode escrever. A conexão do Olist é somente leitura; carregar um arquivo era impossível por construção.
  • O que acontece quando o dado é ruim. O Olist chegou limpo. Bases reais não chegam.

Subir o Metabase localmente devolve as três decisões para você — e cobra o preço de entender a arquitetura por trás do botão.

3. Dois bancos com papéis diferentes

Toda instalação do Metabase envolve dois papéis que iniciantes costumam confundir:

PapelO que guardaNo nosso Compose
Banco da aplicaçãoUsuários, permissões, perguntas salvas, dashboardspostgres-app, banco metabase
Banco analíticoOs seus dados: tabelas carregadas e consultadaspostgres-dados, banco dados

Separá-los não é preciosismo. Um backup do banco da aplicação preserva os seus dashboards e nenhum dos seus dados; restaurar o Metabase em outra máquina sem o banco analítico devolve perguntas que não conseguem responder nada.

4. Por que o docker run de uma linha não serve

A documentação do Metabase abre com um comando único que sobe o servidor em segundos. Ele usa o H2, um banco embutido em arquivo, e é ótimo para dar uma olhada na ferramenta. Para esta aula, ele falha em dois pontos:

  • H2 não suporta upload. A tela de configuração de uploads simplesmente não oferece destino, porque o Metabase só lista bancos onde consegue criar tabelas.
  • H2 vive dentro do contêiner. Sem volume nomeado, remover o contêiner apaga contas, perguntas e dashboards.

Daí o Compose: dois PostgreSQL, um Metabase, volumes nomeados e uma rede interna criada automaticamente.

5. Prática guiada

5.1 Conferir o ambiente

Crie a pasta aula-05-seunome dentro do seu repositório da disciplina e confirme que o Docker responde:

docker --version docker compose version

No GitHub Codespaces o Docker já vem instalado. Em máquina própria, instale o Docker Desktop antes da aula — a primeira instalação não cabe em três horas de laboratório.

5.2 O arquivo docker-compose.yml

Salve o arquivo abaixo dentro da pasta que você acabou de criar. Ele descreve os três serviços e os dois volumes:

services: postgres-app: image: postgres:16 environment: POSTGRES_DB: metabase POSTGRES_USER: metabase POSTGRES_PASSWORD: metabase volumes: - app-data:/var/lib/postgresql/data postgres-dados: image: postgres:16 environment: POSTGRES_DB: dados POSTGRES_USER: aluno POSTGRES_PASSWORD: aluno volumes: - dados-data:/var/lib/postgresql/data metabase: image: metabase/metabase:latest ports: - "3000:3000" environment: MB_DB_TYPE: postgres MB_DB_HOST: postgres-app MB_DB_PORT: 5432 MB_DB_DBNAME: metabase MB_DB_USER: metabase MB_DB_PASS: metabase depends_on: - postgres-app - postgres-dados volumes: app-data: dados-data:

Repare que apenas o Metabase publica porta para fora (3000:3000). Os bancos ficam acessíveis somente dentro da rede do Compose, que é exatamente o que se quer: ninguém alcança o PostgreSQL pela internet.

Senhas neste arquivo são de laboratório

Usuário e senha iguais ao nome do banco servem para uma aula em máquina local, sem porta exposta. Em qualquer ambiente compartilhado ou com acesso externo, credenciais saem do arquivo versionado e vão para variáveis de ambiente ou um gerenciador de segredos.

5.3 Subir a pilha

docker compose up -d docker compose ps docker compose logs -f metabase

A primeira execução baixa cerca de 500 MB de imagens. Depois disso, o Metabase ainda leva de um a três minutos preparando o banco da aplicação: o log para de rolar quando ele estiver pronto. Abra http://localhost:3000 e crie a conta de administrador — ela é local e não tem relação com a conta compartilhada da aula 4.

5.4 Conectar o banco analítico

Em Admin → Databases → Add database, escolha PostgreSQL e preencha:

Host: postgres-dados Port: 5432 Database name: dados Username: aluno Password: aluno

O erro mais comum da aula acontece aqui: escrever localhost no campo Host. Para o contêiner do Metabase, localhost é ele mesmo, não a sua máquina. Dentro de uma rede do Compose, cada serviço é alcançado pelo nome do serviço.

5.5 Ligar o upload

Em Admin → Settings → Uploads, defina dados como banco e public como schema, e salve. Só depois disso o botão de upload aparece nas coleções.

Se a lista de bancos vier vazia, o passo anterior não foi concluído — o Metabase só oferece como destino bancos em que consegue criar tabelas.

5.6 Carregar a base hospitalar

O arquivo é o mesmo dataset sintético do Kaggle usado na próxima aula: Hospital Records for Data Cleaning (Medium), publicado por Nudrat Abbas sob licença CC0. São 5.000 internações fictícias em 7 colunas.

Crie uma coleção, use o botão de upload e selecione o CSV. Três detalhes que valem para qualquer arquivo:

  • Formato: o upload aceita CSV e TSV. Um .xlsx não sobe — no Excel, use Salvar como → CSV UTF-8.
  • Separador: o Excel em português grava ponto e vírgula por padrão. Abra o arquivo em um editor de texto e confira antes de subir.
  • Nomes e tipos: o carregador renomeia colunas e adivinha tipos por conta própria, além de acrescentar uma coluna de identificação interna.

5.7 Antes do SQL, descubra o que subiu

Abra o editor nativo apontando para o banco dados e rode:

SELECT column_name, data_type FROM information_schema.columns WHERE table_name = 'hospital_patients_real_world' ORDER BY ordinal_position;

Esta é a consulta mais importante da aula. Ela devolve os nomes e tipos reais das colunas depois da normalização feita no upload. Adapte todas as consultas seguintes ao que ela retornar: se as datas subiram como texto, por exemplo, a subtração do diagnóstico 7 precisa de uma conversão explícita com CAST(... AS date).

6. Os sete diagnósticos

Cada consulta responde a uma pergunta de qualidade e tem um resultado esperado. Divergência não significa que você errou o SQL — significa que precisa investigar antes de seguir.

6.1 A base chegou inteira?

SELECT COUNT(*) AS linhas FROM hospital_patients_real_world;

Esperado: 5.000. Um número menor costuma indicar arquivo truncado no download ou upload interrompido.

6.2 O que está faltando

SELECT COUNT(*) FILTER (WHERE age IS NULL) AS idade_ausente, COUNT(*) FILTER (WHERE gender IS NULL OR gender = '') AS genero_ausente, COUNT(*) FILTER (WHERE diagnosis IS NULL OR diagnosis = '') AS diagnostico_ausente FROM hospital_patients_real_world;

Esperado: 350, 350 e 350. O teste duplo existe porque carregadores nem sempre convertem campo vazio em nulo: contar só IS NULL pode devolver zero e dar a falsa impressão de base completa.

6.3 Gênero que não informa nada

SELECT COALESCE(NULLIF(gender, ''), 'AUSENTE') AS genero, COUNT(*) AS registros FROM hospital_patients_real_world GROUP BY 1 ORDER BY registros DESC;

Unknown aparece 1.163 vezes e o campo vazio, 350. Somados, são 1.513 registros — perto de 30% da base — sem gênero utilizável. Qualquer recorte por gênero nesta base descreve, na melhor das hipóteses, os 70% restantes.

6.4 Categorias que se duplicam sozinhas

SELECT COUNT(DISTINCT diagnosis) AS categorias_aparentes, COUNT(DISTINCT UPPER(diagnosis)) AS categorias_reais, COUNT(*) FILTER (WHERE diagnosis = UPPER(diagnosis)) AS registros_em_maiusculas FROM hospital_patients_real_world WHERE diagnosis IS NOT NULL AND diagnosis <> '';

Esperado: 28 categorias aparentes, 14 reais e 321 registros escritos em caixa alta. É o tipo de defeito que passa despercebido em uma tabela e explode em um gráfico: Pneumonia e PNEUMONIA viram duas barras, cada uma com metade do volume real.

6.5 Alta antes da admissão

SELECT COUNT(*) AS altas_antes_da_admissao FROM hospital_patients_real_world WHERE dischargedate < admissiondate;

Esperado: 150 registros em que o paciente teria saído antes de entrar. Nenhum deles é apagável sem decisão humana: pode ser inversão de campos no cadastro, erro de digitação de ano ou reinternação mal registrada, e cada hipótese leva a uma correção diferente.

6.6 Duplicidade de paciente

SELECT COUNT(*) AS ids_repetidos FROM ( SELECT patientid FROM hospital_patients_real_world GROUP BY patientid HAVING COUNT(*) > 1 ) repetidos;

Esperado: 0. Registrar o que está correto faz parte do parecer tanto quanto apontar defeitos — sem isso, o leitor não sabe se você verificou ou apenas não olhou.

6.7 A média que engana

SELECT ROUND(AVG(dischargedate - admissiondate), 2) AS permanencia_media, ROUND(AVG(dischargedate - admissiondate) FILTER (WHERE dischargedate >= admissiondate), 2) AS permanencia_media_coerente FROM hospital_patients_real_world;

As duas colunas saem diferentes, e a diferença tem nome: as 150 permanências negativas do diagnóstico 6.5 puxam a primeira média para baixo. Nenhum alerta aparece na tela — o SQL calcula obedientemente a média de um número que não deveria existir. É esse silêncio que torna o parecer necessário.

Diagnóstico não é limpeza

Nenhuma consulta desta aula altera a base. Contar problemas e corrigi-los são atos distintos: o primeiro é reversível e serve de evidência; o segundo exige critério documentado e é o assunto da aula 6. Não use UPDATE ou DELETE aqui, mesmo que a tentação seja grande.

7. Desafio e entrega

Monte um dashboard chamado Confiabilidade da base hospitalar com cinco perguntas salvas: total de linhas, ausências por coluna, categorias aparentes contra reais, registros com cronologia impossível e permanência média com e sem os incoerentes.

Em seguida escreva PARECER_BASE.md, com no máximo dez linhas, respondendo a duas perguntas de forma direta: quais decisões esta base sustenta hoje e quais não sustenta. Cada afirmação precisa citar um número do dashboard.

git add aula-05-seunome/docker-compose.yml aula-05-seunome/PARECER_BASE.md git commit -m "Aula 05: Metabase local e parecer de confiabilidade da base" git push

Critério de aceite: o docker-compose.yml versionado sobe a pilha em outra máquina sem edição; o dashboard tem os cinco cartões preenchidos; o parecer distingue o que a base suporta do que não suporta, citando as contagens 5.000 · 350 · 350 · 350 · 321 · 150 · 0.

8. Checklist de qualidade

  • docker compose ps mostra os três serviços de pé.
  • O banco dados aparece conectado no Metabase e o upload tem destino configurado.
  • A tabela carregada devolve 5.000 linhas.
  • As consultas usam os nomes de coluna que o information_schema devolveu, não os do cabeçalho do CSV.
  • Os sete diagnósticos foram executados e os resultados anotados.
  • Nenhum UPDATE ou DELETE foi executado sobre a base.
  • O parecer separa evidência numérica de recomendação.
  • Ao encerrar, docker compose down preserva os volumes; docker compose down -v apaga tudo.

9. Síntese

Subir a ferramenta é a parte fácil e ocupa vinte minutos da aula. O trabalho está em decidir se o dado merece confiança, e essa decisão só é defensável quando vem acompanhada de contagens que outra pessoa consegue reproduzir.

Três lições viajam para fora do Metabase: upload exige um banco que aceite escrita; carregador nenhum preserva os nomes e tipos que você espera, então confira antes de consultar; e uma média calculada sobre dados incoerentes não emite aviso algum — ela apenas erra em silêncio.

10. Referências e continuidade
