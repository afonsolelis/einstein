Git, grafos e versionamento com Inteligência Artificial

Versionar é tornar uma mudança explicável, comparável e reversível. No case fictício desta aula, Operações, Suprimentos, Controladoria e Dados colaboram em um código de previsão de demanda hospitalar. Você verá o Git como um grafo de versões e usará o GitHub Copilot mantendo decisão, revisão e teste sob responsabilidade humana.

Objetivos de aprendizagem

  • Explicar commit, branch e merge usando um grafo.
  • Criar uma branch e registrar commits pequenos e verificáveis.
  • Comparar versões com status, diff e log.
  • Avaliar uma mudança sugerida por IA antes de aceitá-la.
  • Publicar uma branch e descrever uma proposta de mudança.

1. Case de mercado: previsão compartilhada entre áreas

Um hospital precisa prever admissões por semana para planejar leitos, equipes e insumos. Operações conhece capacidade e calendário; Suprimentos traduz admissões em consumo; Controladoria avalia custos e premissas; a equipe de Dados mantém método e testes. Cópias como previsao_final_v7_agora-vai.py não mostram qual regra foi aprovada e por quem.

O Git permite propostas isoladas em branches, enquanto commits registram intenção e pull requests concentram comparação, discussão e evidências. Este case usa números sintéticos e não inclui prontuários, nomes ou identificadores de pacientes.

2. O que é um grafo?

Um grafo é formado por vértices e arestas. No modelo mental do Git, commits são vértices; relações de ancestralidade apontam para commits anteriores. Como as arestas seguem o tempo para trás e não formam ciclos, o histórico é um grafo direcionado acíclico (DAG).

A ── B ── C ← main
     ╲
      D ── E ← experimento-ia

main e experimento-ia são referências móveis para commits. Uma branch não copia o projeto inteiro: ela aponta para uma linha de evolução.

3. Anatomia de um commit

Um commit contém a fotografia lógica dos arquivos rastreados, metadados, uma mensagem e a referência ao(s) commit(s) pai(s). Seu identificador deriva do conteúdo. Alterar o passado produz outro identificador e outra história.

ConceitoFunção
Working treeArquivos que você está editando.
Staging areaSeleção que entrará no próximo commit.
RepositoryObjetos e histórico registrados em .git.
RemoteOutro repositório, normalmente hospedado no GitHub.

4. O ciclo observar → selecionar → registrar

# Observe antes de agir
git status
git diff

# Selecione e registre uma mudança coerente
git add caminho/do/arquivo
git diff --staged
git commit -m "Explica a decisão tomada"

git add não significa “enviar”; ele prepara a próxima fotografia. git commit registra localmente. git push envia commits para um remoto.

5. Branches, divergência e merge

git switch -c experimento-ia
# editar, revisar e testar
git add .
git commit -m "Adiciona análise sugerida e revisada com IA"
git log --oneline --graph --decorate --all
git push -u origin experimento-ia

Quando duas branches avançam, ocorre divergência. Um merge reúne histórias e pode gerar um commit com dois pais. Um conflito não é uma falha do Git: é uma decisão que a ferramenta não pode tomar sem contexto humano.

6. IA no fluxo: proposta não é evidência

O GitHub Copilot pode explicar código, sugerir uma edição e ajudar a criar testes. Ele também pode produzir lógica incorreta, ignorar restrições ou sugerir dependências inexistentes. Por isso, a IA trabalha dentro de uma branch descartável e cada sugestão passa por inspeção do diff e validação.

Regra de governança

Não envie dados pessoais, segredos, tokens ou conteúdo confidencial ao chat. Leia cada linha sugerida. Aceitar uma sugestão transfere o texto para o projeto, mas não transfere a responsabilidade.

7. Prática guiada: versionar uma previsão com IA

  1. Confirme uma árvore limpa com git status.
  2. Crie a branch experimento-ia-seunome.
  3. Crie previsao_demanda.py com uma média móvel sobre admissões semanais sintéticas.
  4. Faça um primeiro commit manual, simples e funcional.
  5. Peça ao Copilot: “Valide série vazia e valores negativos; crie três testes sem bibliotecas externas. Não use dados pessoais. Explique antes de editar.”
  6. Revise o diff; aceite apenas o que compreender.
  7. Execute python previsao_demanda.py, corrija se necessário e faça um segundo commit.
# Visualize o experimento
git diff
python previsao_demanda.py
git add previsao_demanda.py
git diff --staged
git commit -m "Valida entradas da previsão e revisa sugestão da IA"
git log --oneline --graph --decorate --all

8. Auditoria da sugestão da IA

Registre no arquivo REVISAO_IA.md: prompt utilizado; sugestão recebida; partes aceitas e rejeitadas; teste executado; risco observado; decisão final. Compare o commit manual com o commit assistido. O objetivo não é premiar velocidade, mas demonstrar rastreabilidade.

PerguntaEvidência
A mudança resolve o pedido?Teste funcional e saída esperada.
Introduziu algo fora do escopo?git diff --staged.
Consigo explicar cada linha?Revisão oral em dupla.
É possível desfazer?Commits pequenos e identificáveis.

9. Desafio e entrega

Em dupla, crie duas branches a partir do mesmo commit. A branch operacoes compara a previsão com a capacidade de leitos; a branch suprimentos estima kits consumidos por admissão. Integre as regras sem perder nenhuma área e publique a branch final para uma revisão simulada da Controladoria.

Entrega verificável: branch remota com pelo menos três commits coerentes, saída de git log --oneline --graph --decorate --all, script executável, REVISAO_IA.md preenchido e uma proposta de pull request que explique mudança, teste e risco.

10. Checklist

  • A branch tem nome descritivo e não houve trabalho direto em main.
  • Os commits são pequenos, legíveis e separados por intenção e área.
  • O diff foi revisado antes de cada commit.
  • Os casos normal, série vazia e valor negativo foram testados.
  • A contribuição da IA foi documentada, incluindo rejeições.
  • A base é sintética e nenhum segredo ou dado pessoal aparece no histórico.

11. Síntese

Você modelou o histórico como um grafo, percorreu working tree, staging area e repositório, criou uma linha de trabalho isolada e auditou uma mudança assistida por IA. Git torna a mudança rastreável; testes produzem evidência; revisão humana decide se ela merece integrar o projeto.

12. Continuidade e referências

Na próxima aula, aplicaremos o mesmo fluxo versionado à limpeza de dados com Pandas. Consulte a documentação oficial do Git, do controle de versão em Codespaces e do uso responsável do GitHub Copilot. Recursos e nomes de modos do Copilot podem variar conforme plano e política institucional.
