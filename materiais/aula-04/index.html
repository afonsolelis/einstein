SQL II: laboratório de DDL, DML e DQL

Na aula anterior, construímos o vocabulário da modelagem relacional. Agora o objetivo é ganhar fluência: criar estrutura, registrar mudanças e responder perguntas gerenciais no banco sintético da Rede Cuidar. A maior parte das três horas deve ser usada no editor SQL.

1. Objetivos de aprendizagem

  • Criar tabelas e restrições com DDL.
  • Inserir, atualizar e excluir registros com DML e critérios explícitos.
  • Consultar dados com filtros, ordenação, agregação e JOIN.
  • Validar granularidade, quantidade de linhas e totais antes de interpretar resultados.

2. O ciclo do laboratório

Cada rodada segue o mesmo ciclo: ler a missão, prever o resultado, escrever o SQL, executar, conferir e registrar a evidência. DDL define o contrato do banco; DML altera seu estado; DQL faz perguntas ao estado atual.

DDL → estrutura: CREATE TABLE, ALTER TABLE DML → estado: INSERT, UPDATE, DELETE DQL → pergunta: SELECT, WHERE, GROUP BY, JOIN

Banco de treinamento · sem entrega

Use somente os dados sintéticos fornecidos. O laboratório salva uma cópia no navegador. Se um exercício deixar a base inconsistente, use “Restaurar base” e recomece a rodada. As atividades desta aula servem apenas para praticar.

3. Abra e reconheça o banco

🧪 Abrir laboratório SQL ⬇️ Baixar banco SQLite

Você pode praticar no navegador ou baixar rede-cuidar.sqlite para abrir localmente no SQLite, no DBeaver ou em outra ferramenta compatível.

  1. Liste as tabelas existentes.
  2. Consulte cinco linhas de paciente, medico e atendimento.
  3. Identifique PKs, FKs e a granularidade de cada tabela.
SELECT name, sql FROM sqlite_master WHERE type = 'table'; SELECT * FROM paciente LIMIT 5;

4. Rodada DDL: ampliar o modelo

Crie a entidade convênio e relacione-a ao paciente. Execute um comando por vez e inspecione o esquema após cada mudança.

CREATE TABLE convenio ( convenio_id INTEGER PRIMARY KEY, nome TEXT NOT NULL UNIQUE ); ALTER TABLE paciente ADD COLUMN convenio_id INTEGER REFERENCES convenio(convenio_id);

Checkpoint: tente inserir dois convênios com o mesmo nome e explique por que o segundo comando deve falhar.

5. Rodada DML: alterar com intenção

INSERT INTO convenio (convenio_id, nome) VALUES (1, 'Saúde Mais'), (2, 'Vida Plena'), (3, 'Particular'); UPDATE paciente SET convenio_id = 1 WHERE paciente_id IN (1, 3); UPDATE paciente SET convenio_id = 2 WHERE paciente_id IN (2, 5);

Antes de qualquer UPDATE ou DELETE, execute um SELECT com o mesmo WHERE. A ausência do filtro pode alterar todas as linhas.

SELECT * FROM convenio WHERE convenio_id = 3; DELETE FROM convenio WHERE convenio_id = 3;

6. Rodada DQL: filtrar e ordenar

SELECT atendimento_id, tipo, valor, status FROM atendimento WHERE status = 'Faturado' AND valor >= 300 ORDER BY valor DESC;

Leia a consulta na ordem lógica: origem, filtro, projeção e ordenação. Confira manualmente se todas as linhas satisfazem o critério.

7. Rodada DQL: resumir

SELECT status, COUNT(*) AS quantidade, ROUND(SUM(valor), 2) AS valor_total, ROUND(AVG(valor), 2) AS ticket_medio FROM atendimento GROUP BY status ORDER BY valor_total DESC;

GROUP BY muda a granularidade: cada linha deixa de ser um atendimento e passa a representar um status.

8. Rodada DQL: combinar tabelas

SELECT p.nome AS paciente, COALESCE(c.nome, 'Sem convênio') AS convenio, COUNT(*) AS atendimentos, ROUND(SUM(a.valor), 2) AS receita FROM atendimento AS a JOIN paciente AS p ON p.paciente_id = a.paciente_id LEFT JOIN convenio AS c ON c.convenio_id = p.convenio_id WHERE a.status = 'Faturado' GROUP BY p.paciente_id, c.convenio_id ORDER BY receita DESC;

Use LEFT JOIN quando registros sem correspondência também precisam aparecer. Compare a contagem antes e depois do JOIN para detectar multiplicação indevida.

9. Desafio de treino

Sem entrega: use o tempo para experimentar e comparar soluções para três consultas de negócio:

  1. Receita faturada por especialidade.
  2. Pacientes com mais atendimentos.
  3. Receita por convênio, incluindo pacientes sem convênio.

Meta de aprendizagem: faça cada consulta executar após restaurar a base, escreva nomes de colunas legíveis e confira filtros, JOINs e totais. Você pode apagar tudo e recomeçar quantas vezes quiser.

10. Checklist de qualidade

  • O SQL executa na ordem correta?
  • Chaves e restrições representam a regra de negócio?
  • Cada UPDATE e DELETE possui WHERE conferido?
  • A granularidade da consulta está explícita?
  • O JOIN preserva a quantidade esperada de fatos?
  • Você consegue explicar o resultado encontrado?

11. Síntese

DDL transforma o modelo em contrato; DML registra mudanças; DQL converte o banco em respostas. SQL confiável não é apenas SQL que executa: é aquele cujo resultado pode ser explicado e verificado.

12. Continuidade

Na aula 5, trabalharemos com Pandas para diagnosticar e limpar uma base imperfeita. Nesta aula não há arquivo para entregar: use o laboratório e o banco baixável para treinar no seu ritmo.
