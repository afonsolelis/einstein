O mapa que já conhecemos

PACIENTE 1 ─── N ATENDIMENTO N ─── 1 MÉDICO

Hoje o modelo deixa de ser desenho e passa a responder perguntas executivas.

🧪 Abrir laboratório SQL ⬇️ Baixar banco SQLite

Rodada 1 · reconhecer a estrutura

SELECT name, sql FROM sqlite_master WHERE type = 'table';

Antes de alterar um banco, descubra o que já existe.

DDL · criar CONVÊNIO

CREATE TABLE convenio ( convenio_id INTEGER PRIMARY KEY, nome TEXT NOT NULL UNIQUE );

Execute e confirme a nova tabela em sqlite_master.

DDL · relacionar com PACIENTE

ALTER TABLE paciente ADD COLUMN convenio_id INTEGER REFERENCES convenio(convenio_id);

Uma chave estrangeira materializa a regra de relacionamento.

Checkpoint DDL

  • A tabela convenio existe?
  • A chave primária identifica cada convênio?
  • O nome rejeita repetição?
  • paciente.convenio_id representa a cardinalidade escolhida?

Rodada 2 · INSERT

INSERT INTO convenio (convenio_id, nome) VALUES (1, 'Saúde Mais'), (2, 'Vida Plena'), (3, 'Particular');

DML muda o estado do banco; confira o resultado após executar.

DML · UPDATE com critério

UPDATE paciente SET convenio_id = 1 WHERE paciente_id IN (1, 3); UPDATE paciente SET convenio_id = 2 WHERE paciente_id IN (2, 5);

DML · DELETE sem acidente

SELECT * FROM convenio WHERE convenio_id = 3; DELETE FROM convenio WHERE convenio_id = 3;

Primeiro faça um SELECT com o mesmo WHERE. Só depois remova.

Checkpoint DML

  • Quantas linhas cada comando afetou?
  • O WHERE selecionou somente o alvo?
  • Algum paciente ficou sem convênio?
  • O estado final corresponde à regra de negócio?

Rodada 3 · SELECT e WHERE

SELECT atendimento_id, tipo, valor, status FROM atendimento WHERE status = 'Faturado' AND valor >= 300 ORDER BY valor DESC;

DQL · GROUP BY

SELECT status, COUNT(*) AS quantidade, ROUND(SUM(valor), 2) AS valor_total FROM atendimento GROUP BY status ORDER BY valor_total DESC;

DQL · JOIN

SELECT p.nome AS paciente, c.nome AS convenio, ROUND(SUM(a.valor), 2) AS receita FROM atendimento a JOIN paciente p ON p.paciente_id = a.paciente_id LEFT JOIN convenio c ON c.convenio_id = p.convenio_id WHERE a.status = 'Faturado' GROUP BY p.paciente_id, c.convenio_id ORDER BY receita DESC;

Checkpoint DQL

  • Qual é a granularidade de cada linha?
  • O JOIN multiplicou registros?
  • Filtros foram aplicados antes da agregação?
  • Contagem e soma respondem à pergunta?

Desafio · painel do faturamento

Escreva três consultas para a gerência:

  • Receita faturada por especialidade.
  • Pacientes com mais atendimentos.
  • Receita por convênio, incluindo “Sem convênio”.

Treino livre · sem entrega

  • Teste diferentes filtros e ordenações.
  • Comente a pergunta respondida por cada consulta.
  • Confira os resultados e compare estratégias com os colegas.
  • Restaure a base quando quiser tentar novamente.

Estrutura, estado e pergunta

  • DDL define o contrato.
  • DML altera o estado.
  • DQL transforma dados em respostas.
  • Validação separa uma consulta executada de uma consulta confiável.
